Goal: a new TRAINING approach, a query-conditioned metric-learning patch embedding trained with IN-DRAWING HARD NEGATIVES, so the model learns to separate the query's hatch from other hatches, text and linework on the same sheet.

Design (adjust if you find a concrete reason, and write the reason down):
- Fully convolutional encoder, small (for example 6-8 conv layers, about 1-3 M params, output stride 8, receptive field about 64-96 px at native resolution) plus a second branch on a 2x downsampled image for larger context; concatenate and project to a 64-128 d L2-normalized embedding. Input RGB plus a luminance channel.
- Training data: fit split only (artifacts/splits/fit.json). For a training query, positives are embedding cells inside the reviewed positive region (cells whose center is positive), negatives are cells that are reviewed-known but not positive in the same drawing (hard negatives: other hatches, text, lines). Unknown pixels are never negatives. Anchor is the mean embedding of cells inside the query box. Loss: InfoNCE / supervised contrastive between anchor and cell embeddings with temperature, plus a balanced BCE on cosine similarity; sample crops (for example 512x512 native) that contain both positives and known negatives, plus the query crop; document-balanced sampling; light augmentation (90-degree rotation applied identically to query and target, small scale jitter 0.8-1.25, ink color jitter).
- Inference (label-free): embed the whole drawing in tiles with overlap, compute the query prototype from cells inside the query box, score = cosine similarity mapped to [0,1]; map to reviewed coordinates with a full-image-consistent lookup.
- Write unit tests (CPU, tiny synthetic images) proving: unknown pixels never contribute to loss, labels never reach the inference path, tile stitching equals untiled embedding on a small image.
- Write a training script with explicit seed, steps, learning rate, checkpoint path and a JSON log of losses; and a development scoring script that produces a scores dict for devharness.report (run the harness on compute-box, it only needs numpy/Pillow and the split files).
