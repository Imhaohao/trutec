Read research_v5/BRIEF.txt and research_v5/devharness.py first and obey every rule in the brief. Your directory is research_v5/stacker/ ; create files only there.

Key finding you must design for: positive labels are rectangles of hatched area that INCLUDE text, dimension lines and leaders printed on top of the hatch. A pixel on a letter inside a brick-hatch area is positive. Local-window matchers score those pixels low, so reaching recall 0.98 forces them to accept almost everything. The fix to test is a learned SECOND-STAGE CONTEXT CLASSIFIER (supervised stacking, the supervised replacement for any reinforcement-learning idea): decide each pixel from the pattern evidence in its surroundings, not only at the pixel.

Steps:
1. First-stage evidence maps, full-drawing and label-free, on a stride-8 grid: the texture HGB probability (models/texture-hgb-crop-v1.joblib via inference_texture.py / hatch_texture.py functions; check how inference_texture.py computes the full grid), plus simple label-free ink and chroma maps. Because that HGB was trained on the whole fit split, its fit-split scores are optimistic. Produce honest fit-split first-stage scores by CROSS-FITTING: retrain the same HGB recipe (train_texture.py; read it to reproduce its sampling and settings exactly) in 4 document-grouped folds over the fit split and score each fit query with the model that did not see its document. Use the original model for development queries.
2. Context features per grid cell, all label-free: first-stage score statistics in square windows of several radii (for example 16, 32, 64, 128, 256 px: mean, max, 75th and 90th percentile, fraction above 0.5), the same statistics relative to the query crop's own first-stage score distribution, distance from the query box, ink and chroma fractions, and color mismatch to the query (you may reuse functions in research_v5/color/color_features.py by import).
3. Second stage: HistGradientBoosting on fit-split cells only (real queries plus generated_cad allowed), labels from fit reviewed domains (unknown pixels excluded, never negatives), document-balanced weights. Choose any hyperparameters by grouped cross-validation on fit, not on development.
4. Score all 55 development queries once with the frozen second stage via devharness (map grid scores to the reviewed coordinates with a full-image-consistent lookup), and report best macro IoU, best precision at recall >= 0.98, and the per-query recall at that operating point. Compare with the HGB cache baseline in the brief.

Keep peak memory under 12 GB (process drawings one at a time, sample fit cells, e.g. up to 4000 per query) and 4 CPU threads. Keep research_v5/stacker/findings.txt with exact settings, fold assignments, runtimes, and harness numbers. Run .venv/bin/ruff check research_v5/stacker at the end. Spend up to about 4 hours.
