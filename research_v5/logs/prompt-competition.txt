Read research_v5/BRIEF.txt and research_v5/devharness.py first and obey every rule in the brief. Your directory is research_v5/competition/ ; create files only there.

Goal: build and measure a label-free DRAWING-LEVEL PATTERN COMPETITION matcher. Idea: a drawing contains a small number of distinct hatch patterns plus text, linework and blank paper. Discover them, then predict a pixel as the query's pattern only when its local descriptor is closer to the query than to every competing pattern prototype found in the same drawing.

Steps: (1) compute a multi-scale local texture descriptor on a fixed grid (stride 8 px) over the whole RGB drawing: windowed ink density for luminance and chroma, gradient-orientation histograms, structure-tensor orientation/coherence, and local FFT orientation x period energy; use integral images / box filters so a 7200x4800 sheet takes well under a minute. (2) Remove blank-paper cells, then cluster the remaining cells (mini-batch k-means with several k, or a density-based method) to get prototypes. (3) Build the query prototype from cells inside the query box. (4) Score each cell by a margin: similarity to the query prototype minus the best similarity to any prototype that is not close to the query prototype, converted to [0,1] without labels. (5) Spatially smooth or majority-filter the score over a small neighborhood. Map cell scores to the reviewed coordinates (y, x) with a full-image-consistent lookup.

Measure on all 55 development queries with devharness.report / run_predictor. Also measure fusion with the existing HGB cache (devharness.cached_scores(devharness.HGB_CACHE)). Iterate for up to about 3 hours driven by development numbers; keep research_v5/competition/findings.txt listing each variant, exact settings, and the harness best macro IoU and best precision at recall >= 0.98. Run .venv/bin/ruff check research_v5/competition at the end. Finish with a plain-text summary of what worked, what failed, and the best variant with its numbers.
