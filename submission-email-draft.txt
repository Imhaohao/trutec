Ryan,

I built a system that finds the regions of a construction drawing that match a supplied hatch example and writes a binary mask at the original drawing dimensions. It first cleans the query crop: text glyphs and isolated lines are removed, while families of parallel or connected strokes are kept as the pattern. A texture classifier then scores each location against the cleaned query. A second classifier decides each 8-pixel cell from the evidence in windows of 16 to 256 pixels around it, so text and dimension lines printed on top of a hatched area stay with that area. It also compares line orientation, line spacing and mark size with the query, and it was trained with extra weight on look-alike patterns from the same sheet. A fixed ink-color gate lowers scores where the surrounding ink color disagrees with the query.

The primary result is the frozen v7 pipeline, evaluated by the unchanged official evaluator on all 57 native public-validation masks across 13 documents:

- Document-macro IoU: 88.0003%
- Pooled recall: 98.3112%
- Pooled precision: 68.6909%
- False-discovery fraction FP/(TP+FP): 31.3091%
- Reviewed-negative FPR FP/(FP+TN): 7.4223%
- TP: 628,826; FP: 286,617; FN: 10,802; TN: 3,574,927

For context, my earlier pipelines scored 75.9317% IoU / 97.5775% recall / 32.1327% precision (v2) and 79.8447% / 99.1994% / 50.5034% (v6). v7 cuts false-positive pixels by 78% relative to v2. On 11 of the 13 documents, v7 reaches 95.2% precision, 99.6% recall and a 2.0% reviewed-negative FPR. Most remaining errors come from two dense sheets, where several similar patterns sit side by side.

On validation exposure: public validation was scored for earlier versions, and I inspected v6 errors there to choose what to work on next. These numbers are therefore validation-informed rather than an untouched holdout. No v7 setting was chosen on public validation. The query-cleaning rule was selected on document-held-out scores from real training drawings. The second-stage weighting was selected by document-grouped cross-validation on training data. The 0.25 threshold was chosen on a 55-query development split held out from training, using the same rule as before: highest development IoU with development recall of at least 95%. At that point the development split scored 76.63% IoU, 95.13% recall and 42.06% precision. The pipeline was frozen and hashed before any v7 validation inference. A first launch stopped after 2 seconds on a missing import, before writing any output. The freeze record was amended to hash that file, with no code, model or threshold change. Private-test and whole-sheet accuracy remain unknown. Two public examples are positive-only, and there are no eligible blank pixels for a reviewed-blank FP rate.

Integrity: the native inference path reproduced all 3,465,164 reviewed development decisions at every tested threshold with zero count mismatches. All 57 validation masks are native-size binary PNGs whose IDs match the requests.

Inference took 829.81 seconds for all 57 queries on an Apple M1 Pro with 16 GiB unified memory. Peak memory footprint was 7,499,531,072 bytes, with zero swaps. Runtime covers the whole Python inference process; scoring and packaging are excluded. v7 uses CPU tree models only, with no neural network.
