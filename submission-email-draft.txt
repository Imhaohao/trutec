Ryan,

I built a system that finds the regions of a construction drawing that match a supplied hatch example and writes a binary mask at the original drawing dimensions. A texture classifier scores each location against the query crop. A second classifier, trained on held-out first-stage scores, then decides each 8-pixel cell from the evidence in windows of 16 to 256 pixels around it, so text and dimension lines printed on top of a hatched area are kept with that area. A fixed ink-color gate lowers scores where the surrounding ink color disagrees with the query.

The primary result is the frozen v6 pipeline, evaluated by the unchanged official evaluator on all 57 native public-validation masks across 13 documents:

- Document-macro IoU: 79.8447%
- Pooled recall: 99.1994%
- Pooled precision: 50.5034%
- False-discovery fraction FP/(TP+FP): 49.4966%
- Reviewed-negative FPR FP/(FP+TN): 16.1039%
- TP: 634,507; FP: 621,859; FN: 5,121; TN: 3,239,685

Compared with my earlier v2 pipeline (75.9317% IoU, 97.5775% recall, 32.1327% precision), v6 raises all three and cuts false-positive pixels by 52.8%. It meets the 98% recall goal. The 95% IoU and 95% precision goals remain unmet.

On validation exposure: public validation was scored for earlier versions, so these numbers are validation-informed rather than an untouched holdout. No v6 setting was chosen on public validation. The second-stage settings were chosen by document-grouped cross-validation on my training split. The color-gate setting and the 0.14 threshold were chosen on a 55-query development split held out from training, using the same rule as before (highest development IoU with development recall at least 95%; the selected point was 67.78% IoU, 95.15% recall, 32.63% precision there). The pipeline was frozen and hashed before any v6 validation inference. Private-test and whole-sheet accuracy remain unknown. Two public examples are positive-only, and there are no eligible blank pixels for a reviewed-blank FP rate.

Integrity: the native inference path reproduced all 3,465,164 reviewed development decisions at all 101 tested thresholds with zero count mismatches. All 57 validation masks are native-size binary PNGs whose IDs match the requests.

Inference took 600.89 seconds for all 57 queries on an Apple M1 Pro with 16 GiB unified memory, with a 7,191,626,176-byte peak memory footprint, 4,845,600,768-byte maximum RSS, and zero swaps. Runtime covers the whole Python inference process; scoring and packaging are excluded. v6 uses only CPU tree models and no neural network.
